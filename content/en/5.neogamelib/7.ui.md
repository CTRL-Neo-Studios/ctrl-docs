# UI

NeoGameLib has its own screen-space UI: canvases full of elements, laid out
in UI units with anchors, pivots, sizing modes, padding, and flexbox. It draws
after the world pass, ignores the camera entirely, and scales with the
viewport.

## The model

- **UI units** are layout units; by default 1 UI unit = 1 viewport pixel.
- Elements form a tree under a `NeoCanvas` (the root). Canvases are the only
  roots; you can't put a canvas inside another element.
- The UI bus updates canvases before gameplay each frame and draws them after
  the world pass, one `SpriteBatch` per canvas.
- `NeoGame.OnDrawUI` draws afterwards in raw window pixels, always on top.

```csharp
NeoCanvas canvas = new();
NeoPanel panel = new()
{
    Transform =
    {
        Position = new Vector2(10, 10),
        Size = new Vector2(200, 100),
        Anchor = Vector2.Zero,
        Pivot = Vector2.Zero,
    },
    Color = Color.Gray,
};
NeoLabel label = new() { Text = "HP 100", Color = Color.White }; // Font is borrowed, never disposed by the UI
panel.Children.Add(label);
canvas.Children.Add(panel);
UIBus.Add(canvas);               // updates before gameplay, draws after the world
```

`UIBus` is `NeoGame.UIBus` (a `NeoUIBus`). `Add`/`Remove`/`Clear` manage
registration; a canvas in two buses at once is an error, and `dedupe: false`
lets the same canvas register multiple times in one bus. `NeoCanvas.Subscribe()` /
`Unsubscribe()` default to the singleton bus.

## Canvas

`NeoCanvas` members:

| Member | Default | Meaning |
|---|---|---|
| `Order` | 0 | lower order draws first |
| `ScaleMode` | `ConstantPixelSize` | how UI units map to pixels |
| `ScaleFactor` | 1 | `ConstantPixelSize`: viewport pixels per UI unit |
| `ReferenceResolution` | `(1280, 720)` | `ScaleWithScreen` design resolution |
| `Match` | 0 | `ScaleWithScreen` blend: 0 = width, 1 = height, between = log-space blend |
| `PixelPerfect` | false | whole-number scale (min 1) + point sampling |
| `Scale` | — | computed pixels-per-unit, updated each pass |
| `Children` | — | element tree |
| `ScreenToCanvas(Vector2)` | — | window pixels → UI units (letterbox + scale aware) |
| `CanvasToScreen(Vector2)` | — | UI units → window pixels |

The canvas layout size is `viewport / Scale`, so anchors, padding, flexbox,
and `Fit` all work in UI units regardless of resolution.

### Scaling

```csharp
NeoCanvas debug = new() { ScaleFactor = 2f };   // 1 UI unit = 2 pixels

// design at 1280x720, grow/shrink with the viewport:
NeoCanvas hud = new()
{
    ScaleMode = NeoCanvasScaleMode.ScaleWithScreen,
    ReferenceResolution = new Vector2(1280, 720),
    Match = 1f,
    PixelPerfect = true,
};
```

`Match` blends in log space (Unity-style): 0.5 treats a 2x-wider viewport the
same as a 2x-taller one. With `ViewportAspect` set to the reference ratio
(e.g. 16:9 for 1280x720), every `Match` value yields the same scale.

::callout{icon="i-lucide-info" color="primary"}
SpriteFonts are bitmaps: text scaled way up gets blurry. Load a bigger font
for big scale ranges.
::

## ScreenTransform

Every element has `element.Transform`, a `ScreenTransform`. It inherits the
world `Transform` (`Position`, `Rotation`, `Scale`, `Up`/`Down`/`Right`/`Left`),
plus:

| Member | Default | Meaning |
|---|---|---|
| `Size` | `(0, 0)` | the element's own size in UI units (used by `Fixed`) |
| `Anchor` | `(0.5, 0.5)` | where the element sits in its parent: 0 = left/top, 1 = right/bottom |
| `Pivot` | `(0.5, 0.5)` | its own origin point |
| `WidthMode` / `HeightMode` | `Fixed` | sizing per axis (below) |
| `DesiredSize` | — | computed content size (read-only) |
| `LayoutPosition` | — | top-left of the box from the last pass (read-only) |
| `LayoutSize` | — | box size from the last pass (read-only) |
| `HasVisualTransform` | — | true when Rotation/Scale deviate from identity |

`Transform` is get-only; set members with the nested initializer
`Transform = { ... }`.

**Placement formula:**

```
top-left = parent top-left + parent size * Anchor + Position - own size * Pivot
```

(For children of padded containers, "parent" is the padded inner box.)
Canvases and flexbox-managed children ignore `Anchor`/`Pivot`.

**Rotation and Scale** behave like a CSS transform: they rotate/scale the
element and its subtree around the pivot for drawing and hit testing, but
layout, `Fit`, and flexbox use the untransformed box — a rotated button does
not push its neighbors. A rotated/scaled element costs one extra
`SpriteBatch` pass for its subtree. The canvas's own rotation/scale do
nothing (use the canvas scale settings).

## Sizing modes

`NeoUISizing` per axis (`WidthMode`, `HeightMode`):

| Mode | Behavior |
|---|---|
| `Fixed` | use `Size` |
| `Fill` | take the parent's full inner length; in a flexbox, `Fill` shares leftover space on the main axis and stretches on the cross axis |
| `Fit` | wrap the content: measured text for labels/buttons, or a box holding all children |

Labels and buttons default to `Fit` on both axes. To give a button a fixed
size, set the modes back to `Fixed` and set `Size`.

## Elements

### NeoPanel

A solid rectangle:

```csharp
NeoPanel card = new()
{
    Transform = { WidthMode = NeoUISizing.Fit, HeightMode = NeoUISizing.Fit },
    Color = Color.Gray,
    Padding = new NeoPadding(16, 8),   // 16 left/right, 8 top/bottom
};
```

- `Color` — tint (`Alpha = 0` skips drawing).
- `Padding` — per-side inner spacing; children anchor to the padded box,
  `Fill` takes the inner size, `Fit` adds padding around children.

`NeoPadding` constructors: `(all)`, `(horizontal, vertical)`,
`(left, top, right, bottom)`; implicit from `float`; settable per side
(`new NeoPadding(8) { Bottom = 24 }`). Negative or non-finite values throw.

### NeoFlexBox

A panel that orders children in a `Row` or `Column`:

```csharp
NeoFlexBox menu = new()
{
    Direction = NeoFlexDirection.Column,
    Gap = 8, Padding = 12,
    Justify = NeoFlexAlign.Center,     // main axis
    Align = NeoFlexAlign.Stretch,      // cross axis
    Transform = { WidthMode = NeoUISizing.Fit, HeightMode = NeoUISizing.Fit },
    Color = Color.DarkSlateGray,
};
menu.Children.Add(new NeoButton { Text = "Play", Font = font });
menu.Children.Add(new NeoButton { Text = "Quit", Font = font });
```

| Member | Meaning |
|---|---|
| `Direction` | `Row` (ltr) or `Column` (ttb) |
| `Gap` | UI-unit gap between children on the main axis |
| `Justify` | child placement on the main axis: `Start` (default), `Center`, `End`, `SpaceBetween` (extra gap distributed) |
| `Align` | child placement on the cross axis: `Start` (default), `Center`, `End`, `Stretch` (fill cross length), `SpaceBetween` (stretches like `Stretch`) |

`Fill`-mode children share leftover main-axis space equally (after fixed
children and gaps). Flexbox children ignore their anchors/pivots.

### NeoLabel / NeoButton

```csharp
NeoLabel label = new() { Text = "HP 100", Font = font, Color = Color.White };

NeoButton play = new()
{
    Text = "Play", Font = font,
    Transform = { Anchor = Vector2.Zero, Pivot = Vector2.Zero },
};
play.OnClick = () => StartGame();
```

- `NeoLabel`: `Text`, `Font`, `Color`. Draws at native text size — no
  wrapping, scaling, or clipping.
- `NeoButton`: clickable label. `OnClick` fires when the left button is
  pressed and released over the button. `HoverColor`/`PressedColor` tint the
  hover/pressed states; `Hovered` is exposed. Reads the `Input` facade, so it
  needs a running game.
- Both default to `Fit` sizing; the font is borrowed, never disposed.

### NeoImage

```csharp
NeoImage icon = new() { Texture = tex, Color = Color.White };
icon.Transform.Size = new Vector2(32, 32);   // scales texture to the box
```

Draws the texture (or `SourceRectangle`) stretched to the layout box.

## Custom elements

Subclass `NeoUIElement` and override:

- `OnUpdate(GameTime)` — runs every update pass while `Enabled` (subtree-gated).
- `OnDraw(SpriteBatch)` — runs every draw pass while `Visible` (batch begun,
  in element space).
- `MeasureContent()` — the element's own content size; `Fit` takes the larger
  of this and the children box.

```csharp
public class HealthBar : NeoUIElement
{
    public float Value;                 // 0..1
    public Texture2D Pixel;             // your own 1x1 white texture

    protected override Vector2 MeasureContent() => new(100, 8);

    protected override void OnDraw(SpriteBatch sb)
    {
        Vector2 pos = ScreenTransform.LayoutPosition;
        Vector2 size = ScreenTransform.LayoutSize;
        sb.Draw(Pixel, pos, null, Color.Red, 0, Vector2.Zero, size, SpriteEffects.None, 0);
        sb.Draw(Pixel, pos, null, Color.Green, 0, Vector2.Zero,
            new Vector2(size.X * Value, size.Y), SpriteEffects.None, 0);
    }
}
```

(`NeoPanel` uses an internal 1x1 white pixel; custom elements that draw
rectangles need their own.)

Element members you'll touch: `Children`, `Parent`, `ScreenTransform`
(=`Transform`), `Enabled` (updates), `Visible` (draws — independent of
`Enabled`), `Canvas` (walk up to the root), `VisualMatrix`.

## Hit testing

```csharp
bool over = element.ContainsScreenPoint(Input.MousePosition);  // inside the DRAWN box:
// letterbox, canvas scale, rotation, scale all handled
Vector2 local = element.ScreenToLocal(Input.MousePosition);    // window px -> layout space
Vector2 screen = canvas.CanvasToScreen(element.Transform.LayoutPosition); // UI units -> px
```

Buttons already do all of this; use `ContainsScreenPoint` for custom elements.

## Draw order within the UI

- Canvases draw in `Order` (then registration), each in its own scaled batch.
- Within a canvas, parent draws before children, children in add order.
- Rotated/scaled subtrees get their own batch pass.
- Everything UI draws after the world pass; `OnDrawUI` draws last.

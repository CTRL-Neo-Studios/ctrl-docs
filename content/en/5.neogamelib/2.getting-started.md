# Getting Started

## Install

Initialize your project with MonoGame first, then:

::code-group

```bash [dotnet cli]
dotnet add package NeoGameLib
```

```xml [csproj]
<PackageReference Include="NeoGameLib" Version="0.3.2" />
```

::

Running the same `dotnet add` command again pulls the latest version.

## The minimum working game

Inherit `NeoGame` instead of `Game`:

```csharp
using Microsoft.Xna.Framework;
using Microsoft.Xna.Framework.Content;
using Microsoft.Xna.Framework.Graphics;

public class MyGame : NeoGame
{
    protected override void OnLoadContent(ContentManager cm)
    {
        // create and register a world
        WorldManager.CreateWorld("level1", world =>
        {
            NeoObject player = world.Instantiate("Player", new Transform(new Vector2(100, 100)));
            player.AddComponent(new NeoSpriteRenderer(RenderBus, cm.Load<Texture2D>("player")));
        });

        WorldManager.Load("level1");
    }

    protected override void OnUpdate(GameTime gameTime)
    {
        // runs after input + UI, before worlds, collisions and timers
    }

    protected override void OnDraw(SpriteBatch spriteBatch, GameTime gameTime)
    {
        // draws inside the main camera's world-space batch (identity when no camera exists)
    }

    protected override void OnDrawUI(SpriteBatch spriteBatch, GameTime gameTime)
    {
        // draws in plain window pixels, above every canvas
    }
}
```

In `Program.cs`, run your game the normal MonoGame way:

```csharp
using var game = new MyGame();
game.Run();
```

### The five lifecycle hooks

`NeoGame` seals MonoGame's own `Initialize`/`LoadContent`/`Update`/`Draw` and
exposes five virtual hooks instead:

| Hook | Runs | Typical use |
|---|---|---|
| `OnInitialize()` | once, after all buses exist and content has loaded | one-time game setup |
| `OnLoadContent(ContentManager)` | once, after `Content` is ready (fires before `OnInitialize`) | load assets, create/load worlds |
| `OnUpdate(GameTime)` | every frame, before worlds update | frame-level logic |
| `OnDraw(SpriteBatch, GameTime)` | every frame, in the main camera's world batch | custom world-space drawing |
| `OnDrawUI(SpriteBatch, GameTime)` | every frame, last, in window pixels | debug overlays, screen-space drawing |

Buses and managers exist before `OnInitialize` and `OnLoadContent` run, so
component constructors that take a bus argument can be used in `OnLoadContent`
directly.

## The frame, in order

`NeoGame.Update` runs everything in a fixed order every frame:

1. **Input** — input maps refresh first; every later stage reads this frame's input.
2. **Viewport** — the letterboxed viewport (see `ViewportAspect`) is re-applied.
3. **UI update** — canvases lay out and handle their own logic.
4. **`OnUpdate`** — your game hook.
5. **Worlds** — every loaded world ticks: components get `OnStart` (first tick)
   and `OnUpdate`, destroyed objects flush.
6. **Collisions** — the collider bus resolves pairs and fires `ICollision`
   callbacks (so it sees positions from *this* frame's world update).
7. **Timers** — timer ticks run last.

`Draw` runs three passes: the world pass (once per enabled camera, sprites then
text), the UI pass (one batch per canvas), then `OnDrawUI` in raw window pixels.

## One design rule that makes everything else make sense

Every frame-loop in the library walks a **snapshot** of its list
(`PassSnapshot<T>`). That is the reason you can, from inside any callback
(`OnUpdate`, `OnCollision`, `OnDestroy`, a timer callback, `OnDraw`...),
safely:

- load/unload worlds
- destroy objects or add/remove components
- start/stop timers
- add/remove cameras, sprites, or canvases

Things you change mid-pass take effect **next tick**. When you write your own
loops over world objects or components, use `PassSnapshot<T>` and check
`IsAttached`/`IsDestroyed` per item — see
[Game Objects](/3.game-objects#iterating-yourself-passsnapshot).

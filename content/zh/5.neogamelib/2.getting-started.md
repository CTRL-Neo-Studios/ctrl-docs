# 快速上手

## 安装

先初始化你的 MonoGame 项目，然后：

::code-group

```bash [dotnet cli]
dotnet add package NeoGameLib
```

```xml [csproj]
<PackageReference Include="NeoGameLib" Version="0.3.2" />
```

::

再次运行同样的 `dotnet add` 命令会拉取最新版本。

## 最小可运行游戏

继承 `NeoGame` 而不是 `Game`：

```csharp
using Microsoft.Xna.Framework;
using Microsoft.Xna.Framework.Content;
using Microsoft.Xna.Framework.Graphics;

public class MyGame : NeoGame
{
    protected override void OnLoadContent(ContentManager cm)
    {
        // 创建并注册一个世界
        WorldManager.CreateWorld("level1", world =>
        {
            NeoObject player = world.Instantiate("Player", new Transform(new Vector2(100, 100)));
            player.AddComponent(new NeoSpriteRenderer(RenderBus, cm.Load<Texture2D>("player")));
        });

        WorldManager.Load("level1");
    }

    protected override void OnUpdate(GameTime gameTime)
    {
        // 在输入 + UI 之后、世界/碰撞/计时器之前运行
    }

    protected override void OnDraw(SpriteBatch spriteBatch, GameTime gameTime)
    {
        // 在主摄像机的世界空间批处理中绘制（没有摄像机时为单位矩阵）
    }

    protected override void OnDrawUI(SpriteBatch spriteBatch, GameTime gameTime)
    {
        // 以纯窗口像素绘制，位于所有画布之上
    }
}
```

在 `Program.cs` 中以普通 MonoGame 的方式运行游戏：

```csharp
using var game = new MyGame();
game.Run();
```

### 五个生命周期钩子

`NeoGame` 密封了 MonoGame 自身的 `Initialize`/`LoadContent`/`Update`/`Draw`，
改而暴露五个虚方法钩子：

| 钩子 | 运行时机 | 典型用途 |
|---|---|---|
| `OnInitialize()` | 一次，在所有总线存在且内容加载完成之后 | 一次性游戏设置 |
| `OnLoadContent(ContentManager)` | 一次，在 `Content` 就绪之后（先于 `OnInitialize` 触发） | 加载资源、创建/加载世界 |
| `OnUpdate(GameTime)` | 每帧，在世界更新之前 | 帧级逻辑 |
| `OnDraw(SpriteBatch, GameTime)` | 每帧，在主摄像机的世界批处理中 | 自定义世界空间绘制 |
| `OnDrawUI(SpriteBatch, GameTime)` | 每帧，最后，以窗口像素 | 调试覆盖层、屏幕空间绘制 |

总线和管理器在 `OnInitialize` 与 `OnLoadContent` 运行之前就已存在，
因此可以直接在 `OnLoadContent` 中使用接收总线参数的组件构造函数。

## 每帧的执行顺序

`NeoGame.Update` 每帧按固定顺序运行所有内容：

1. **输入** —— 输入映射最先刷新；之后的每个阶段读取的都是本帧输入。
2. **视口** —— 重新应用信箱式视口（见 `ViewportAspect`）。
3. **UI 更新** —— 画布完成布局并处理自身逻辑。
4. **`OnUpdate`** —— 你的游戏钩子。
5. **世界** —— 每个已加载世界逐帧 tick：组件在首帧收到 `OnStart`，
   之后每帧 `OnUpdate`，被销毁的对象出队清理。
6. **碰撞** —— 碰撞总线解析重叠对并触发 `ICollision` 回调（因此它看到的
   是*本帧*世界更新后的位置）。
7. **计时器** —— 计时器 tick 最后运行。

`Draw` 分三个通道运行：世界通道（每个启用的摄像机一次，先精灵后文本）、
UI 通道（每个画布一个批处理）、最后以原始窗口像素运行 `OnDrawUI`。

## 一条让其他一切都说得通的设计规则

库中的每个帧循环都在遍历其列表的**快照**（`PassSnapshot<T>`）。这就是为什么
你可以在任何回调（`OnUpdate`、`OnCollision`、`OnDestroy`、计时器回调、
`OnDraw`……）内部安全地：

- 加载/卸载世界
- 销毁对象或增删组件
- 启动/停止计时器
- 增删摄像机、精灵或画布

你在遍历中途所做的修改会**在下一帧**生效。当你自己遍历世界对象或组件时，
请使用 `PassSnapshot<T>` 并逐项检查 `IsAttached`/`IsDestroyed` —— 见
[游戏对象](/3.game-objects#iterating-yourself-passsnapshot)。

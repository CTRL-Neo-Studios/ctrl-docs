# UI

NeoGameLib 有自己的屏幕空间 UI：画布装满元素，以 UI 单位布局，支持锚点、枢轴、
尺寸模式、内边距和弹性盒。它在世界通道之后绘制，完全无视摄像机，并随视口缩放。

## 模型

- **UI 单位**是布局单位；默认 1 UI 单位 = 1 视口像素。
- 元素在 `NeoCanvas`（根）之下构成一棵树。画布是唯一的根；不能把画布放进另一个
  元素里。
- UI 总线每帧在玩法之前更新画布，并在世界通道之后绘制它们，每个画布一个
  `SpriteBatch`。
- `NeoGame.OnDrawUI` 之后以原始窗口像素绘制，永远在最上层。

```csharp
NeoCanvas canvas = new();
NeoPanel panel = new()
{
    Transform =
    {
        Position = new Vector2(10, 10),
        Size = new Vector2(200, 100),
        Anchor = Vector2.Zero,
        Pivot = Vector2.Zero,
    },
    Color = Color.Gray,
};
NeoLabel label = new() { Text = "HP 100", Color = Color.White }; // Font 为借用，UI 从不释放它
panel.Children.Add(label);
canvas.Children.Add(panel);
UIBus.Add(canvas);               // 在玩法之前更新，在世界之后绘制
```

`UIBus` 即 `NeoGame.UIBus`（一个 `NeoUIBus`）。`Add`/`Remove`/`Clear` 管理注册；
一个画布同时在两个总线中会报错，`dedupe: false` 允许同一画布在一个总线中注册
多次。`NeoCanvas.Subscribe()` / `Unsubscribe()` 默认使用单例总线。

## Canvas

`NeoCanvas` 成员：

| 成员 | 默认值 | 含义 |
|---|---|---|
| `Order` | 0 | 越小越先绘制 |
| `ScaleMode` | `ConstantPixelSize` | UI 单位如何映射到像素 |
| `ScaleFactor` | 1 | `ConstantPixelSize`：每 UI 单位的视口像素数 |
| `ReferenceResolution` | `(1280, 720)` | `ScaleWithScreen` 的设计分辨率 |
| `Match` | 0 | `ScaleWithScreen` 混合：0 = 跟随宽度，1 = 跟随高度，中间值 = 对数空间混合 |
| `PixelPerfect` | false | 整数倍缩放（最小 1）+ 点采样 |
| `Scale` | — | 计算出的每单位像素数，每个通道更新 |
| `Children` | — | 元素树 |
| `ScreenToCanvas(Vector2)` | — | 窗口像素 → UI 单位（计入信箱与缩放） |
| `CanvasToScreen(Vector2)` | — | UI 单位 → 窗口像素 |

画布布局尺寸为 `viewport / Scale`，因此锚点、内边距、弹性盒和 `Fit` 都按 UI 单位
工作，与分辨率无关。

### 缩放 {#scaling}

```csharp
NeoCanvas debug = new() { ScaleFactor = 2f };   // 1 UI 单位 = 2 像素

// 以 1280x720 设计，随视口放大缩小：
NeoCanvas hud = new()
{
    ScaleMode = NeoCanvasScaleMode.ScaleWithScreen,
    ReferenceResolution = new Vector2(1280, 720),
    Match = 1f,
    PixelPerfect = true,
};
```

`Match` 在对数空间中混合（Unity 风格）：0.5 把宽 2 倍的视口和 高 2 倍的视口
同等对待。当 `ViewportAspect` 设为参考宽高比（例如 1280x720 对应 16:9）时，任何
`Match` 值都得到完全相同的缩放。

::callout{icon="i-lucide-info" color="primary"}
SpriteFont 是位图：文本放大太多会变糊。缩放范围大时请加载更大的字体。
::

## ScreenTransform

每个元素都有 `element.Transform`，一个 `ScreenTransform`。它继承了世界
`Transform`（`Position`、`Rotation`、`Scale`、`Up`/`Down`/`Right`/`Left`），
另加：

| 成员 | 默认值 | 含义 |
|---|---|---|
| `Size` | `(0, 0)` | 元素自身尺寸，UI 单位（`Fixed` 使用） |
| `Anchor` | `(0.5, 0.5)` | 元素在父容器中的位置：0 = 左/上，1 = 右/下 |
| `Pivot` | `(0.5, 0.5)` | 自身的原点 |
| `WidthMode` / `HeightMode` | `Fixed` | 逐轴尺寸模式（见下文） |
| `DesiredSize` | — | 计算出的内容尺寸（只读） |
| `LayoutPosition` | — | 最近一次通道的盒子左上角（只读） |
| `LayoutSize` | — | 最近一次通道的盒子尺寸（只读） |
| `HasVisualTransform` | — | Rotation/Scale 偏离单位值时返回 true |

`Transform` 是只读的；用嵌套初始化器 `Transform = { ... }` 设置成员。

**摆放公式：**

```
左上角 = 父左上角 + 父尺寸 * Anchor + Position - 自身尺寸 * Pivot
```

（对有内边距容器的子元素来说，"父"是内边距内的盒子。）画布和弹性盒管理的
子元素忽略 `Anchor`/`Pivot`。

**旋转与缩放**表现得像 CSS transform：它们在绘制和命中测试时围绕枢轴旋转/缩放
元素及其子树，但布局、`Fit` 和弹性盒使用未变换的盒子 —— 旋转的按钮不会挤开
邻居。旋转/缩放的元素会为其子树多花一个 `SpriteBatch` 通道。画布自身的
旋转/缩放不起作用（用画布的缩放设置代替）。

## 尺寸模式

`NeoUISizing` 逐轴生效（`WidthMode`、`HeightMode`）：

| 模式 | 行为 |
|---|---|
| `Fixed` | 使用 `Size` |
| `Fill` | 占满父容器的内部长度；在弹性盒中，`Fill` 在主轴上分享剩余空间，在交叉轴上拉伸 |
| `Fit` | 收缩到内容尺寸：标签/按钮的测量文本，或容纳所有子元素的盒子 |

标签和按钮默认双轴 `Fit`。要给按钮固定尺寸，把模式改回 `Fixed` 并设置 `Size`。

## 元素

### NeoPanel

一个纯色矩形：

```csharp
NeoPanel card = new()
{
    Transform = { WidthMode = NeoUISizing.Fit, HeightMode = NeoUISizing.Fit },
    Color = Color.Gray,
    Padding = new NeoPadding(16, 8),   // 左右 16，上下 8
};
```

- `Color` —— 色调（`Alpha = 0` 跳过绘制）。
- `Padding` —— 各边的内部间距；子元素锚定到有内边距的盒子，`Fill` 取内部尺寸，
  `Fit` 在子元素周围加上内边距。

`NeoPadding` 构造函数：`(all)`、`(horizontal, vertical)`、
`(left, top, right, bottom)`；可从 `float` 隐式转换；可逐边设置
（`new NeoPadding(8) { Bottom = 24 }`）。负值或非有限值抛异常。

### NeoFlexBox

一个按 `Row` 或 `Column` 排列子元素的面板：

```csharp
NeoFlexBox menu = new()
{
    Direction = NeoFlexDirection.Column,
    Gap = 8, Padding = 12,
    Justify = NeoFlexAlign.Center,     // 主轴
    Align = NeoFlexAlign.Stretch,      // 交叉轴
    Transform = { WidthMode = NeoUISizing.Fit, HeightMode = NeoUISizing.Fit },
    Color = Color.DarkSlateGray,
};
menu.Children.Add(new NeoButton { Text = "Play", Font = font });
menu.Children.Add(new NeoButton { Text = "Quit", Font = font });
```

| 成员 | 含义 |
|---|---|
| `Direction` | `Row`（从左到右）或 `Column`（从上到下） |
| `Gap` | 主轴方向子元素之间的 UI 单位间距 |
| `Justify` | 主轴上的子元素摆放：`Start`（默认）、`Center`、`End`、`SpaceBetween`（额外间距平均分配） |
| `Align` | 交叉轴上的子元素摆放：`Start`（默认）、`Center`、`End`、`Stretch`（填满交叉长度）、`SpaceBetween`（与 `Stretch` 一样拉伸） |

`Fill` 模式的子元素平均分享主轴剩余空间（在固定尺寸子元素和间距之后）。弹性盒
子元素忽略自己的锚点/枢轴。

### NeoLabel / NeoButton

```csharp
NeoLabel label = new() { Text = "HP 100", Font = font, Color = Color.White };

NeoButton play = new()
{
    Text = "Play", Font = font,
    Transform = { Anchor = Vector2.Zero, Pivot = Vector2.Zero },
};
play.OnClick = () => StartGame();
```

- `NeoLabel`：`Text`、`Font`、`Color`。按文本原生尺寸绘制 —— 不换行、不缩放、
  不裁剪。
- `NeoButton`：可点击的标签。`OnClick` 在左键于按钮上方按下并松开时触发。
  `HoverColor`/`PressedColor` 给悬停/按下状态上色；`Hovered` 对外暴露。它读取
  `Input` 门面，因此需要游戏正在运行。
- 两者默认 `Fit` 尺寸；字体为借用，永不释放。

### NeoImage

```csharp
NeoImage icon = new() { Texture = tex, Color = Color.White };
icon.Transform.Size = new Vector2(32, 32);   // 把纹理拉伸到盒子大小
```

把纹理（或 `SourceRectangle`）拉伸绘制到布局盒子。

## 自定义元素

继承 `NeoUIElement` 并覆写：

- `OnUpdate(GameTime)` —— 启用（`Enabled`，作用于子树）时每个更新通道运行。
- `OnDraw(SpriteBatch)` —— 可见（`Visible`）时每个绘制通道运行（批处理已 Begin，
  处于元素空间）。
- `MeasureContent()` —— 元素自身的内容尺寸；`Fit` 取它和子元素盒子的较大者。

```csharp
public class HealthBar : NeoUIElement
{
    public float Value;                 // 0..1
    public Texture2D Pixel;             // 你自己的 1x1 白色纹理

    protected override Vector2 MeasureContent() => new(100, 8);

    protected override void OnDraw(SpriteBatch sb)
    {
        Vector2 pos = ScreenTransform.LayoutPosition;
        Vector2 size = ScreenTransform.LayoutSize;
        sb.Draw(Pixel, pos, null, Color.Red, 0, Vector2.Zero, size, SpriteEffects.None, 0);
        sb.Draw(Pixel, pos, null, Color.Green, 0, Vector2.Zero,
            new Vector2(size.X * Value, size.Y), SpriteEffects.None, 0);
    }
}
```

（`NeoPanel` 使用内部 1x1 白色像素；绘制矩形的自定义元素需要自备。）

你会用到的元素成员：`Children`、`Parent`、`ScreenTransform`（= `Transform`）、
`Enabled`（更新）、`Visible`（绘制 —— 独立于 `Enabled`）、`Canvas`（向上走到根）、
`VisualMatrix`。

## 命中测试

```csharp
bool over = element.ContainsScreenPoint(Input.MousePosition);  // 是否在绘制出的盒子内：
// 信箱、画布缩放、旋转、缩放全部处理
Vector2 local = element.ScreenToLocal(Input.MousePosition);    // 窗口像素 -> 布局空间
Vector2 screen = canvas.CanvasToScreen(element.Transform.LayoutPosition); // UI 单位 -> 像素
```

按钮已经做了所有这些；自定义元素用 `ContainsScreenPoint` 即可。

## UI 内部的绘制顺序

- 画布按 `Order`（再按注册顺序）绘制，各自在自己的缩放批处理中。
- 画布内部，父元素先于子元素绘制，子元素按添加顺序。
- 旋转/缩放的子树获得自己的批处理通道。
- 所有 UI 都在世界通道之后绘制；`OnDrawUI` 最后绘制。
